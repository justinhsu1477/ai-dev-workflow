## 八、碩億的業務場景分析（為什麼特別適合我們）

### 客製化開發的痛點 vs 這套系統的解法

| 痛點 | 說明 | 系統怎麼解決 |
|------|------|-------------|
| 每案需求不同 | WMS、OCDS 每案都有客製邏輯 | AI 根據頁面自動規劃測試，不用每案寫測試腳本 |
| 改 A 壞 B | ERP 模組互相關聯，改訂單影響庫存 | Push 後自動跑受影響模組的 E2E，馬上抓到迴歸 bug |
| 客戶不接受 bug | 企業客戶對品質要求高 | 上線前 AI 先抓一輪，減少客戶回報 |
| 沒有專職 QA | 開發跟測試是同一批人 | AI 當 24 小時不休息的 QA |
| 同時維護多專案 | 3-5 個客戶同時進行 | 一套中間件服務所有專案 |

### 一套中間件，服務所有客戶專案

```
                    ┌─────────────┐
                    │ AI Workflow  │  ← 只維護這一套
                    │ Middleware   │
                    └──────┬──────┘
                           │
          ┌────────────────┼────────────────┐
          │                │                │
    ┌─────▼─────┐   ┌─────▼─────┐   ┌─────▼─────┐
    │ 味全 OCDS  │   │ 客戶B WMS  │   │ 客戶C ERP │
    └───────────┘   └───────────┘   └───────────┘
```

**每個專案只需要設定自己的 `e2e-module-mapping.yml`**，定義：
- 有哪些模組（訂單、庫存、出貨...）
- 每個模組的測試路由和步驟提示
- 登入帳號和角色

中間件程式碼完全共用，新增一個客戶專案 = 新增一份 YAML 設定檔，不需要寫任何程式。

### 碩億每月的實際效益估算

| 指標 | 估算 |
|------|------|
| 同時進行專案 | 3-5 個 |
| 每月 push 次數 | ~100-200 次 |
| 客戶回報的 bug | ~10-30 個/月 |
| 每個 bug 處理時間（含客戶溝通） | 3-8 小時 |
| **每月花在 bug 的時間** | **30-240 小時** |
| 導入後預計攔截率 | 40-60% 的 bug 在上線前被抓到 |
| **每月省下** | **12-144 小時** |
| 多專案 API 費用（3-5 個專案） | ~$60-100/月 |

### 導入前 vs 導入後對比

| 場景 | 沒有這套系統 | 有這套系統 |
|------|------------|-----------|
| 客戶回報 bug | 工程師花半天查、半天修 | AI 在上線前就抓到了 |
| 做完 A 功能，B 壞了 | 客戶先發現，然後客訴 | Push 後 5 分鐘就知道 |
| 客戶驗收前 | 工程師手動點一遍所有功能 | AI 自動跑一輪，出報告 |
| 新人接手維護 | 不知道改了會影響什麼 | AI 自動測受影響的模組 |
| 新增客戶專案 | 要重新寫測試 | 新增一份 YAML 設定檔即可 |

### 給老闆的一句話（碩億版）

> 「我們做客製化開發，最怕改 A 壞 B、客戶驗收才發現 bug。
> 這套系統讓每次 push 後 5 分鐘就知道有沒有壞東西，
> 而且一套中間件服務所有客戶的專案，新增專案只要加一份設定檔。
> API 費一年不到一萬台幣，等於請了一個 24 小時不休息的 QA。」

## 十、建議行動方案

1. 先在 OCDS Web 專案 pilot 1-2 個月
2. 收集實際數據：bug 偵測數、修復成功率、省下的時間

4. （長期）可考慮商品化，賣給其他用 Azure DevOps 的公司
